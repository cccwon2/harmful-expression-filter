# 52. 트레이(Tray) 시스템 정리

이 문서는 `electron/tray.ts`에 구현된 시스템 트레이(System Tray)의 구조, 기능 및 상태 관리 방식을 정리합니다.

## 1. 개요
시스템 트레이는 애플리케이션이 백그라운드에서 실행될 때 사용자와 상호작용하는 주요 진입점입니다. `electron/tray.ts`는 트레이 아이콘 생성, 컨텍스트 메뉴 구성, 그리고 다양한 시스템 상태(오디오, 오버레이, 설정 등)와의 연동을 담당합니다.

## 2. 파일 위치
- **경로**: `electron/tray.ts`
- **주요 역할**: 트레이 아이콘 관리, 컨텍스트 메뉴 동적 업데이트, IPC 이벤트 핸들링

## 3. 주요 기능 및 구조

### 3.1 동적 아이콘 생성 (`createTrayIcon`)
트레이 아이콘은 정적 이미지가 아닌, 현재 상태에 따라 픽셀 버퍼를 직접 조작하여 동적으로 생성됩니다.
- **크기**: 32x32 픽셀 (RGBA)
- **상태 표시**:
  - **모니터링 중 (스트리밍)**: 초록색 배경 (#10b981)
  - **대기 중**: 파란색 배경 (#2563eb)
- **디자인**: 중앙에 "H" (Harmful Filter) 텍스트가 그려진 심플한 아이콘.

### 3.2 컨텍스트 메뉴 (`updateContextMenu`)
트레이 메뉴는 애플리케이션의 상태가 변경될 때마다 `updateContextMenu` 함수를 통해 재생성됩니다. 이를 통해 UI와 내부 상태의 동기화를 유지합니다.

#### 주요 메뉴 항목
1.  **영역 지정 (Select Region)**
    *   OCR 모드로 전환하여 화면의 특정 영역을 인식하도록 설정합니다.
    *   `ipc/dashboardHandlers`의 `switchToOcrMode`를 호출하거나, 실패 시 기존 Setup 모드로 폴백합니다.
2.  **오버레이 제어 (Show/Hide Overlay)**
    *   오버레이 윈도우의 가시성을 토글합니다.
    *   오버레이가 표시될 때 `Edit Mode`를 자동으로 활성화하고, 마우스/키보드 포커스를 설정합니다.
3.  **편집 모드 (Edit Mode)**
    *   오버레이의 클릭 통과(Click-through) 여부를 결정하는 모드입니다.
    *   활성화 시 마우스 이벤트를 오버레이가 수신하고, 비활성화 시 배경으로 통과시킵니다.
4.  **개발자 도구 (Toggle DevTools)**
    *   오버레이 윈도우의 개발자 도구를 `detach` 모드로 엽니다.
    *   개발자 도구 사용 중에도 마우스 이벤트 처리가 가능하도록 예외 처리가 되어 있습니다.
5.  **오디오 캡처 (Audio Capture)**
    *   `AudioManager`를 통해 특정 프로세스(Chrome, Edge, Discord)의 오디오를 캡처하고 스트리밍합니다.
    *   현재 스트리밍 상태를 메뉴 라벨에 표시합니다.
6.  **볼륨 설정 (Volume)**
    *   시스템 볼륨이 아닌 앱 내부 처리 볼륨을 조절합니다 (1~9단계).
    *   `store`를 통해 값을 영구 저장합니다.
7.  **블러 강도 설정 (Blur Intensity)**
    *   유해 텍스트 가림막의 블러 강도를 조절합니다 (15px, 25px, 40px).
8.  **민감도 설정 (Sensitivity/Threshold)**
    *   유해성 판단 임계값을 0.0 ~ 1.0 사이에서 0.1 단위로 조절합니다.
9.  **사용자 대시보드**
    *   관리자/사용자 대시보드 윈도우를 엽니다.

### 3.3 상태 관리 및 연동
트레이 시스템은 다양한 외부 모듈과 긴밀하게 연동되어 있습니다.

- **`AudioManager`**: 오디오 스트리밍 상태 확인 및 제어.
- **`store`**: 볼륨, 블러 강도, 민감도(Threshold) 등의 설정값 저장 및 로드.
- **`overlayWindow`**: 윈도우의 가시성(`show`, `hide`) 및 포커스 제어.
- **`editMode`**: 오버레이의 마우스 이벤트 처리 방식 제어 (`setIgnoreMouseEvents`).

## 4. 이벤트 처리
- **Double Click**: 트레이 아이콘을 더블 클릭하면 오버레이 윈도우를 토글합니다. 이는 메뉴의 "Show/Hide Overlay"와 동일한 동작을 수행하며, 사용자 편의성을 높입니다.
- **Window Events**: `overlayWindow`의 `show`, `hide` 이벤트를 감지하여 트레이 메뉴의 상태(라벨 등)를 즉시 업데이트합니다.

## 5. 개선 사항 및 참고 (Refactoring Notes)
- `tray.ts` 파일의 크기가 커짐에 따라 메뉴 구성 로직을 별도 모듈로 분리하는 것을 고려할 수 있습니다.
- 아이콘 생성 로직(`createTrayIcon`)을 별도 유틸리티로 분리하여 재사용성을 높일 수 있습니다.
- 메뉴 아이템의 상태 업데이트 로직이 복잡하므로, 상태 관리 패턴(예: Observer)을 도입하여 결합도를 낮출 수 있습니다.
